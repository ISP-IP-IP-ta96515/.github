<p>检测这件事分两条线，一条查地址登记在哪，一条查这段线路跑得好不好。本文先说两条线的分工，再讲归属要看的三处记录、质量要看的四个数字，然后给两张对照表，最后说明结果互相矛盾时该怎么判断，以及多久复检一次。</p>
<h2>一、检测分成归属和质量两条线</h2>
<p>归属回答的是这段地址登记在谁名下、属于哪个城市、以什么方式接入。它决定平台第一眼怎么看你。</p>
<p>质量回答的是延迟、丢包、带宽这些使用体验。它决定你能不能干活，跟归属是两件独立的事。</p>
<p>两条线都要跑。归属合格但线路抖动，业务做不下去；线路很好但登记在市场不对的国家，一样白搭。</p>
<h2>二、归属先看三处登记</h2>
<p>第一处是 whois，看 netname 和注册组织。组织名跟运营商对得上，说明这段地址确实由运营商分配。</p>
<p>第二处是 ASN，看自治域编号属于哪家。住宅段的 ASN 通常是当地宽带运营商，不是机房或云服务商。</p>
<p>第三处是反向解析。rDNS 里带运营商命名规则的，可信度更高；空着或者写成通用模板的，要多问一句。</p>
<p>三处记录最好来自两个不同渠道。域名查询站给 whois，路由查询站给 ASN，两者对着看比单看一处可靠。</p>
<h3>地理位置是第四处但最不可靠</h3>
<p>多数查询站的经纬度来自登记库，误差能到几十公里，甚至全国都指向首都。城市级判断要结合 ASN 一起看。</p>
<h2>三、质量看四个数字</h2>
<p>延迟看平均值和最大值，两者差距大说明线路在排队。只看平均，会把一条抖动的线当成好线。</p>
<p>丢包要在高峰时段测。闲时零丢包不代表晚八点也零丢包，而业务恰恰集中在那个时段。</p>
<p>带宽要单线程测。多线程能把数字堆上去，但网页加载和后台操作多是单连接，单线程才反映体感。</p>
<h3>抖动比延迟更难忍</h3>
<p>延迟稳定在两百毫秒，操作节奏是顺的；忽高忽低到四百，点下去都不知道会不会生效，这种线更难用。</p>

<p>顺序建议由静到动，先查登记，再查路由，然后测延迟和丢包，最后跑真实业务。前面的结果能解释后面的异常。</p>

<p>测的时候把结果存成文件，日期、出口地址、延迟、丢包四项就够。下次复测拿出来一比，趋势比单次数字有用。</p>
<h2>六、结果互相矛盾怎么判断</h2>
<p>常见矛盾是 ASN 对但城市不对。这多半是登记库没更新，实际接入点仍在该运营商网内，可以要线路证明。</p>
<p>另一种是显示住宅但延迟低得离谱。低到不像跨境，就要怀疑测的是机房内网或者本地代理。</p>
<p>判断原则是先信技术指标，再信页面标签。标签来自数据库，指标来自你眼前这条链路。</p>
<h3>别忘记录一次基线</h3>
<p>第一次检测的结果要留着当基线。以后觉得慢了，跟基线比，才知道是自己线路退化还是对方做了调整。</p>
<h2>常见问答</h2>
<h3>免费查询站的结果可信吗？</h3>
<p>答：可作初筛。它们的库更新慢，城市级信息常有偏差，关键结论最好用两处以上来源交叉确认。</p>
<h3>检测要跑多久才算数？</h3>
<p>答：至少覆盖一个完整的高峰时段。只看白天的十分钟，容易把拥塞问题整个漏掉。</p>
<h3>ASN 属于运营商就一定是住宅吗？</h3>
<p>答：不一定。运营商也会出租机房段。还要看接入类型和 rDNS 的命名规则，三者一起判断。</p>
<h3>检测不通过要不要马上退？</h3>
<p>答：先分清是哪一项不通过。登记问题基本无解，质量波动可以复测，别把偶发当成结论。</p>
